# Phase 3 llama.cpp Runtime Integration

Date: 2026-05-19

## Strategy

Use an external llama.cpp checkout and local-only static libraries. The app repo
does not vendor llama.cpp source or model files.

The default project still builds without llama.cpp. The real llama.cpp path is
activated only when `LocalLlama/OnDeviceLlama.local.xcconfig` exists and defines:

```text
SCREENTRANSLATOR_LLAMA_CPP_ENABLED=1
```

That local config is generated by:

```bash
tools/on_device_llama/build_llama_ios_static.sh
```

## What Is Implemented

`OnDeviceLlamaBridge.mm` now contains a guarded real llama.cpp implementation.
When the compile flag and headers are available, it:

- loads all ggml backends,
- loads `tiny-test.gguf` from the app Documents path,
- tokenizes the existing hardcoded translation-style prompt,
- creates a llama context,
- uses a greedy sampler,
- decodes up to 32 tokens,
- returns generated text and timing metrics,
- frees sampler, context, and model resources,
- maps failures into `OnDeviceLlamaBridgeResult`.

When llama.cpp is not available, the bridge keeps returning the safe fallback
error.

## Local Build Workflow

Install CMake first. Then run:

```bash
cd /Users/notnik_kg/Desktop/Programming/ScreenTranslator/ScreenTranslator
tools/on_device_llama/build_llama_ios_static.sh
```

The script clones or reuses:

```text
/Users/notnik_kg/Desktop/Programming/ScreenTranslator/External/llama.cpp
```

and writes local-only outputs under:

```text
LocalLlama/
```

The first conservative build is CPU-only:

- `GGML_METAL=OFF`
- `GGML_ACCELERATE=OFF`
- `GGML_OPENMP=OFF`
- `n_gpu_layers=0`

This is intentional. Metal can be added later after the tiny CPU smoke test
proves the load/generate path on a real iPhone.

## Real iPhone Test Steps

1. Run `tools/on_device_llama/build_llama_ios_static.sh`.
2. Open the project in Xcode.
3. Build the `ScreenTranslator` scheme in Debug for a real iPhone.
4. Install and launch the app once.
5. Put a tiny GGUF model named `tiny-test.gguf` in the app Documents directory.
6. Open Settings.
7. Tap `Open Smoke Test`.
8. Tap `Run Smoke Test`.
9. Confirm:
   - status is `success`,
   - output text is non-empty,
   - load/generation/total durations are visible,
   - token count is visible,
   - no Quick Look path is invoked.

## Model Placement

The app expects:

```text
Documents/tiny-test.gguf
```

Do not commit the model. Use Xcode Devices and Simulators to download/replace
the app container, or add a temporary DEBUG-only importer in a later phase.
